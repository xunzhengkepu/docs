改话术后仍会遇到的问题：原因、修复路径与验收

结论：规范话术可以减少语义和作品指向歧义，但不能补齐任务身份、媒体证据、状态出口和执行链路。当前最应优先处理的是整句关键词拦截、把示例当事实、已定时后的返修与取消路径。已修复的历史问题不再作为当前故障重复列出。

1. 本次分析范围与证据强度

重新梳理本聊天中从edge case、window、状态转换、历史修复，到员工话术规范的全部讨论，并读取当前本地代码及已有修复回执。没有读取其他聊天，没有重新查询生产数据库或核验部署版本。因而“当前代码存在”不等于“生产已发生”，“旧待核对记录”也不等于“截至今天仍未解决”。

  • 已复现：调用当前纯函数，以合成中文消息检查规则和校验结果。共6组输入；没有模型API调用、数据库操作或微信操作。
  • 代码缺口／边界：静态检查转换、关联、AI输入与调用门槛，说明能力范围，不能直接计入线上错误率。
  • 历史待核对：只依据已有回执；需最新证据才能关闭。
  • 风险／建议：明确标作未证实，不包装为事故或已完成修复。

函数检查的任务、角色、初始状态均为预设；AI校验输入是人工构造的提案，不是实际模型回答。其中规则和AI输出不一致的例子，不代表两者会在同一生产调用中同时执行。查看6组合成函数检查结果。

3. 改话术后剩余的15类问题与边界

P0表示建议先做的错误状态或外部发布风险控制；P1为主要业务与运行完整性；P2为证据治理与质量改进。优先级是建议，不代表已经发生事故。

1. 已复现：事实与问句、否定句混在一起，被整句拦截

P0 · 可修复
现象／证据
“成片已剪好，请问今天审核可以吗？”规则不推进，校验也拒绝已交付提案；“已设置定时，尚未发布”同样被拒绝。
为什么改话术仍不能完全解决
问号、尚未等按整条文本匹配，未判断它们修饰哪个动作。改话术能绕开部分情况，但员工自然补一句询问就会复发。
如何修复或改善（建议，未实施）
先提取带原话跨度的事件：动作、对象、是否完成、时间、否定作用范围；仅对当前事件校验。保留任务和角色门槛；无法区分时待核对。不要直接删除所有否定保护。
如何验收
覆盖同句多个动作、问句、双重否定、标题问号；已完成交付＋询问应记录交付，单纯询问不得推进。

2. 已复现：示例文字可能被当成实际完成

P0 · 可显著降低，不能仅靠关键词消除
现象／证据
在预设任务、运营身份、待发布状态下，“这是参考话术：已发布。”被规则提出已发布；人工构造同样模型提案也通过校验。
为什么改话术仍不能完全解决
关键词匹配缺少“这句话是在陈述事实，还是引用示例”的检查。统一话术反而可能让群内培训文本出现更多完成关键词。
如何修复或改善（建议，未实施）
识别引用、模板、培训、转述等语境；高影响发布事件要求当前作品的实际完成声明。对语境不明确的规则提案增加语义核验，而非仅在规则无结果时才调用AI。
如何验收
加入模板转发、引用旧回执、别人的发布、真实发布对照样本；检查是否最终落库，不能只验证模型输出。

3. 已复现：规则与AI校验口径不一致

P1 · 可修复
现象／证据
“原来是定时发布，现在已发布成功。”规则允许已发布，但AI校验因含“定时”拒绝。
为什么改话术仍不能完全解决
两条路径各自维护文本规则，词语作用范围不同。当前规则已提出结果时通常不走AI补充，因此这不是已确认的端到端失败。
如何修复或改善（建议，未实施）
共用事件语义与转换约束；校验以当前事实片段为单位。让规则与AI输出同一事件结构，再走统一验证。
如何验收
同一事件走规则路径、AI路径，应得到一致的可接受结果；保留真实转发与未来计划反例。

4. 代码缺口：已定时后的返修和取消

P0 · 可修复，须明确业务规则
现象／证据
已定时状态收到医生“字幕改一下”时，普通规则不推进，校验拒绝成片修改事件；取消定时也没有自动退回路径。
为什么改话术仍不能完全解决
状态转换集合未包含这些出口；一句清楚的话无法新增合法转换。发布排期和制作进度实际上是两个事实。
如何修复或改善（建议，未实施）
分别记录返修要求与排期状态；取消请求不等于平台已取消。取消回执确认后更新排期，按明确规则恢复制作阶段；取消未确认时保留风险待办，不能伪造平台撤销。
如何验收
覆盖请求、成功、失败、晚到发布回执、取消期间返修；模拟平台，禁止测试真实取消或发送。

5. 代码边界：已发布、暂停、异常等没有自动恢复路径

P1 · 可扩展，不应取消保护
现象／证据
受保护状态会停止普通自动推进。
为什么改话术仍不能完全解决
这是现有保护设计；后续返修、下架、恢复需要独立事件，不能仅换话术绕过。
如何修复或改善（建议，未实施）
为下架请求／完成、暂停解除等建立独立受控入口，保留原状态与历史；恢复前核验新增证据。发布记录按平台区分，避免单个平台下架误作全平台下架。
如何验收
验证历史只追加、重复事件幂等、恢复后不覆盖人工更正；多平台为需确认的设计场景，非已证实故障。

6. 正常待核对：任务或文件仍可能指向不唯一

P1 · 可降低；真实歧义需要人确认
现象／证据
同标题、同医生多个相近作品、引用错文件、一次描述多条作品。旧7条错绑及M197310已修复，不能称仍然错绑。
为什么改话术仍不能完全解决
话术清晰不保证引用正确；当前关联优先标题或引用，也保留有限上下文推断。
如何修复或改善（建议，未实施）
推荐引用＋任务短ID；引用与标题冲突继续拦截。候选相似度只作证据；人工确认后保存来源并受控重放受影响消息。
如何验收
同名作品、跨任务引用、并行交付、引用丢失、人工绑定后重放；不降低唯一性要求换通过率。

7. 代码边界：批量话术不一定支持批量推进

P1 · 可扩展
现象／证据
关联器遇到多个明确task或“这两条／这批”等会返回多任务；另外存在批量处理入口，需按事件类型验证范围。
为什么改话术仍不能完全解决
一个明确批量句也可能需要多个独立事件，不能把范围清楚等同于所有批量类型均已支持。
如何修复或改善（建议，未实施）
先按所列任务展开候选事件，逐任务校验角色、阶段和证据；报告部分成功与失败，禁止含糊地整体推进。
如何验收
两条不同阶段、仅其中一条批准、列表与附件数量不一致；不能把当前代码概括为完全不支持批量。

8. 信息不足：身份和业务类型不能由话术替代

P1 · 映射错误可修复；缺事实需补齐
现象／证据
类型未知、未知账号、客户称“通过”等仍可能无法进入科普自动流程。M199564/M199361等只有历史待核对记录。
为什么改话术仍不能完全解决
谁有权批准、任务属于哪种业务，是结构化事实。措辞规范不能赋予审批权限。
如何修复或改善（建议，未实施）
核实账号与角色适用范围；录入经确认的业务类型并保留来源；冲突转人工。不得用群名或药物关键词推断类型，也不让模型自行提升权限。
如何验收
客户批准、账号变化、同人多角色、患教与科普冲突；补齐后受控重试。

9. 持续技术风险：上传声明不等于媒体可用

P1 · 可改善，不能保证全自动
现象／证据
原片仍受下载、文件身份、时长、ASR、唯一80%匹配约束；150秒及以下视频走证据保留；超过120秒仍可能无有效匹配。
为什么改话术仍不能完全解决
说“已上传”不会修复下载失败、低信噪比、即兴改稿或多个相似候选。逐段补转和下载幂等重试已经实现，不应再次列作缺失。
如何修复或改善（建议，未实施）
保留现有重试；按明确原因区分下载失败、音频不足、内容改写和候选冲突。短视频若需自动化，先确认业务需求后另设路径；困难匹配增加经验证的证据或人工关联，不直接降低门槛。
如何验收
分别报告真实ASR效果、离线匹配和原生下载验证；M196476需按最新策略复核，旧分数不能代表当前。

10. 证据边界：文字交付不证明实际内容及质量

P1 · 可通过分层记录改善
现象／证据
AI可记录剪辑师明确交付回执，但视频可能尚未下载核验；医生批准也不应由员工转述自动代替。
为什么改话术仍不能完全解决
话术描述的是人的声明，系统验证的是另一层事实。
如何修复或改善（建议，未实施）
分开记录“员工报告已交付”“文件可读且任务匹配”“医生已批准”；对外显示依据层级，是否要求媒体验证再进入某阶段需明确业务决定。
如何验收
空附件、错误附件、已交付但损坏文件、仅转述批准；不能把文字路径一律称作bug。

11. 未证实风险：上下文窗口和截断遗漏证据

P2 · 可改善
现象／证据
AI输入同群同任务最多12条历史，每条最多2000字符，当前消息最多4000字符；任务关联另有最近10条和10分钟等局部边界。
为什么改话术仍不能完全解决
标准话术仍可能依赖很早的批准、撤销或引用；仅扩大窗口也可能混入其他作品。
如何修复或改善（建议，未实施）
优先按明确引用、任务事件和未解决修改取证；保留已确认状态摘要及来源，标记截断；不足时补检索或待核对。
如何验收
构造跨窗口修改、批准后撤销、长消息截断样本。当前没有证据把某次线上错误归因于窗口。

12. 配置与运行风险：AI理解正确也未必被采用

P1 · 可观测、可修复
现象／证据
AI补充要求启用、适用策略、已关联任务和已知角色；shadow只记录建议，apply才采用；仅对部分规则结果调用。
为什么改话术仍不能完全解决
话术不会改变配置、角色门槛或服务可用性。规则错误地直接提出状态时，也可能不进入AI补充。
如何修复或改善（建议，未实施）
检查实际运行版本和安全配置摘要，展示规则结果、AI是否调用及原因、校验结果与最终落库；对429/超时沿用受控重试和失败隔离。
如何验收
fake API故障、模式切换、重启幂等；检查现有机制后补缺，不声称当前未启用或没有重试。

13. 运行风险：历史、并发和外部同步

P1 · 可降低、可恢复
现象／证据
迟到消息、人工改状态、同一任务并发更新，以及本地状态与外部展示不同步仍可能出现。
为什么改话术仍不能完全解决
规范消息不能让跨系统写入成为一个事务。当前已有CAS、历史、outbox和人工保护。
如何修复或改善（建议，未实施）
保留现有保护，明确区分已识别、已落库、已同步；失败告警与对账，重放前检查更新版本和后续事实，不强制覆盖人工结果。
如何验收
模拟并发、网络超时、成功回执丢失、重复消息；查队列与回读证据后才能判定线上故障。

14. 历史数据不会因新话术自动变好

P2 · 可修复有证据的历史记录
现象／证据
老消息仍可能缺对象或类型，已处理的旧决策不会因为规范发布就自动重算。
为什么改话术仍不能完全解决
规范只影响后续输入；全量重跑可能覆盖人工修正或重复作用。
如何修复或改善（建议，未实施）
按已知待办清单做只读重评，比较原判定、当前证据和建议；仅对明确目标做受控修复，保留旧历史。
如何验收
M197310关联已修、M197999选版已核实；类型或批准未确认的部分继续独立列出，不重新打开已关闭关联问题。

15. 已确认文档问题：旧说明与后续修复不一致

P2 · 可修复
现象／证据
旧说明称M197310/M197999未关闭，后续回执已核实；旧说明也未完整反映AI文字交付路径。
为什么改话术仍不能完全解决
文档和案例状态没有随实现、回执同步，导致此前聊天把已修问题再次当作现存故障。
如何修复或改善（建议，未实施）
每个问题保存独立编号、修复时间、证据、残余待办和部署核验；按仓库规则新增版本，旧版注明历史适用范围，避免凭旧章节下结论。
如何验收
索引指向新版本；案例状态与回执一致；已改代码、已部署、已复核三个标签分开。

4. 建议实施顺序

  1. 先补6个复现输入的端到端回归。把纯函数证据升级为临时数据库测试，确认原始消息、关联、规则、AI提案校验、最终落库各层差异。不能把函数提案直接认定为生产已写错。
  2. 修复事件级语义校验。将“动作已完成”与后面的询问、否定其他动作分开；模板和转述不得直接作为完成事实；规则与AI共用约束。
  3. 补齐排期与返修闭环。明确取消请求、取消成功、返修、发布回执的关系，再改状态机、数据库约束和对应处理入口。
  4. 补任务与身份的可核查关联。引用、任务ID、证据冲突、人工绑定及受控重放先打通，再考虑更大范围自动化。
  5. 做运行可观测与历史整理。按问题展示模型是否调用、结果是否采纳、是否落库和同步、谁来处理剩余待办；用最新回执更新文档版本。

5. 修复后的验收要求

后续代码修改必须运行 npm run test:video-golden 及涉及模块测试；不得改写或删除既有frozen覆盖以求通过。业务规则改变时按既有版本流程新增样本并保留旧版。

  • 状态转换：临时数据库验证允许与禁止路径、历史只追加、幂等及人工保护。
  • 文本判断：分别验证规则、AI适配器、校验层及最终落库；真实模型调用评测与离线测试分开报告。
  • 涉及语音／Qwen时：另跑对应适配器、转写队列、视频开头测试；真实ASR准确率不能以golden替代。
  • 运行故障：模拟超时、429、回执丢失、并发更新、版本冲突；不得向真实联系人发消息、重启微信或改写生产业务数据。
