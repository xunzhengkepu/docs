01 · 当前系统结构

当前系统由 Windows 微信本地采集、Node.js 后台调度、Python 业务判定、PostgreSQL 业务库与附件台账、云端聊天预览、飞书状态同步组成。它不是一条“下载→上传→改状态”的串行流水线，而是共享消息身份的几条并行流程。

微信消息 / 本地文件↓ 采集归档，产生消息 UID
任务与状态

稿件正文 → 作品身份 → 本地 task → 交接证据 → 状态历史 → 飞书队列

附件获取

找本地文件 → 准备下载 → 原生执行 → 观察文件 → 原件核验

网页展示

预览需求 / 原件就绪通知 → 提取或转码 → 上传预览 → 云端缓存 → 浏览器展示

附件原件与转写证据进入任务判定；预览上传成功本身不触发状态推进。

本文是 2026-11-10 的代码阅读与已有运行证据总结。本次仅制作文档，不修改业务代码、微信配置或飞书数据。问题数量引用各自标注的审计快照，不冒充实时重新统计。

03 · 什么时候创建 task？

A. 已有飞书作品

目录导入读取既有作品，建立或维护本地业务任务与飞书记录的对应关系。这属于既有作品登记，不是新规则凭消息创造一个新作品。

B. 新收到的稿件

  1. 消息进入已识别的医生群，发送人角色能够核验。当前稿件身份解析入口允许已识别的文案、医生或剪辑人员；但“文案交稿”的状态事件另要求文案职责，二者不是同一个判断。
  2. 读取实际稿件正文：支持可解析的文档和符合稿件结构的文本。只有文件名或“我写好了”不足以证明正文已取得。
  3. 在该医生范围内比较已有稿件正文和显式关联（当前正文相似度门槛0.8）：唯一匹配则复用任务；多个相似任务、引用与正文冲突、同标题不同正文则待核对。
  4. 确实没有已有任务，并通过启用时间等检查时，创建本地 task。ID由稿件来源 UID稳定生成，重试不会随意创建新ID。
  5. 同一事务写入初始状态、版本1历史、来源与医生关系；默认显示“文案确认中”。内容类型可以仍是“未知”，后续自动流转只处理明确科普作品。

初始登记不等于一次阶段推进；创建本地 task 也不等于创建飞书作品。当前 feishuCreateEnabled=false，只允许更新原18位医生已存在作品的状态。

视频到达后进入视频目录、原件检查与稿件匹配。找不到唯一稿件时记待核对，不应因为视频到达就随意新建作品。稿件版本关系和“一文件多稿”识别仍是主要缺口。

04 · 什么时候下载图片和视频？

  1. 发现附件：从消息归档读取图片/视频，先检查已有本地文件与先前完成记录。下载范围由附件配置决定，不能把它等同于飞书原18医生写入白名单。
  2. 形成下载需求：启用自动下载后，按消息时间、群范围、是否自己发送等条件扫描。网页前台预览需求也可请求原图或提高视频优先级；被动预览不等于主动下载。
  3. 准备：构造对应消息的下载参数、校验ID/UID，加入就绪队列。ready只表示参数准备好。
  4. 执行：通过共享串行通道，检查登录账号、进程绑定、版本、忙碌与冷却等条件，再调用原生下载封装。
  5. 等待：原生返回异步对象只代表请求已提交。观察器继续查本地文件，区分未出现、不完整、缩略图和完整文件。
  6. 完成或失败：文件证据满足要求才记下载完成；超时、撤回、源不可用、重试耗尽分别记录，不能用统一“下载失败”代替。

图片要区分原图/清晰图/缩略图；视频要有完整文件、大小与时长等证据。图片预览已有缩略图时，清晰图仍可能下载失败。

55秒是信立泰原18医生的视频分析门槛，不是附件下载门槛。短视频仍可能被下载和预览。已发布或已关闭任务的历史原件缺口按已确认要求归档，不列为必须恢复的待处理。

05 · 什么时候预览、什么时候上传？

阶段触发与操作不能据此推断
本地消息→云端消息cloud-sync同步消息文字和元信息，让网页先知道有这条消息。消息出现在网页，不代表附件字节已经上传。
形成预览任务云端已有预览请求；另有source-ready后台通知，让已落地原件进入预览准备。当前图片/视频自动就绪通知扫描最近72小时。72小时是该通知路径窗口，不是所有消息保留时间，也不代表窗口外文件损坏。
图片预览领取任务→提取本地图片→压缩预览→上传。非被动图片任务可排入原图获取队列；先拿到缩略图也可形成预览。缩略图上传成功≠清晰图或原图完成；视频封面上传≠视频本体上传。
视频预览领取任务→定位本地源→转码MP4→等待云端容量→流式上传。前台原生视频任务可提高下载优先级，短时等待本地源出现。local_video_missing发生在找源/准备阶段，不能笼统称为“播放器故障”。以文件方式发送的视频不走原生视频消息下载通道。
服务端接收上传成功回执入台账，云端预览可供浏览器访问。图片原件另有独立同步通道。历史HTTP成功不证明现在仍能播放；缓存淘汰、URL失效、浏览器播放另需核验。
缓存管理预览是可再生成的缓存，受容量和清理规则约束；本地临时转码文件上传后清理。云端预览不是所有业务原件的永久备份。

保留“本地”和“云端”是为了区分两个事实：微信原件是否取得，以及网页可访问的预览是否生成。它们服务不同步骤，可以一端成功、另一端失败。

06 · 怎么确定状态转换？

事件目标状态必须有的证据
文案人员交出实际稿件或修改稿文案确认中正文可读、稿件身份与作品唯一对应
文案人员真实引用稿件并承接修改文案修改中文案职责、真实引用、本作品稿件
医生交付原片待剪辑原件核验、适用时长、唯一作品匹配
剪辑人员交出成片或新版成片成片确认中剪辑职责、原件核验、唯一作品匹配
剪辑人员真实引用成片并承接修改剪辑中真实引用本作品当前成片
发布人员真实引用最终成片并承接发布待发布发布职责、真实引用、明确目标成片
可核验的平台发布结果已发布作品对应、平台/URL/平台视频ID及确认信息

当前规则版本是 handoff-seven-20261106-v1。原18医生配置55秒及以上进入分析；旧策略文件仍保留用于兼容与Golden验证，不能只看到旧文件里的150秒就认定当前全局仍用150秒。

  1. 识别群、医生、发送人职责及交接事件，普通闲聊不触发。
  2. 匹配唯一任务，核验正文、原件或真实引用。只说“好的”“可以”不等于已发布。
  3. 视频先检查原件身份，再做Qwen语音转写与同医生稿件匹配。转写从开头按20秒分段扩展，最多120秒或视频结束，并非统一只转写55秒。
  4. 规则决定目标；比较当前状态、人工保护、事件先后、允许的阶段迁移。同阶段重复是正常结果；较早消息只补证据，不回退后续状态。
  5. 事务内比较状态版本，成功后更新tasks并追加status_history。判定结果、来源消息、关联方式一并保存；冲突则不强行推进。

新规则主视频原件核验不依赖SHA256，使用来源关联、文件路径/大小/时间标记等证据。上传完整性、消息/事件ID、缓存版本及兼容旧逻辑仍使用哈希，不能把“取消视频流转依赖”解释成代码里不能出现SHA256。

已取消、已下架是人工状态；已定时、待录制保留兼容或未来使用，不属于当前七种自动目标。数据库仍保留“文案待医生确认”“成片待医生确认”历史别名，展示为“文案确认中”“成片确认中”。

07 · 本地变更后，什么时候改飞书？

本地状态事务成功↓ 当时已有飞书record_id，才生成outbox检查绑定启用、保护标志、前序队列↓ 读取飞书作者身份和当前状态确认原18医生＋唯一目标表＋作品进度字段↓ 远端状态符合预期才写；不一致保留差异写后再次读取 → verified

本地推进和飞书发送是两个阶段。缺绑定时可能本地成功而无发送记录；后来绑定不会自动补建旧版本队列。前序冲突会阻塞同任务后续发送。目录导入会跳过无效/空状态，绑定可能被停用。

当前同步开关已恢复，仅允许 Base VSbobBKbGaNq6IsgqdocVqiunnd 的医生视频表 tblSWYAlZu4PVGgV、原18位医生、“作品进度”字段 fldPwWdcpd。医生信息总表只读，不改其他医生、其他字段，不自动创建作品。本地落后时不覆盖飞书人工进度。

08 · 台账能解释什么，仍缺什么？

attachment_ledger.attachments是附件当前阶段摘要；attempts是每次尝试及其最新结果；events追加记录阶段事件与历史证据。尝试与摘要会更新，不能把整个台账称为全部只追加；追溯应看events及尝试关联。

台账把prepare、native_dispatch、download、transcode、upload等阶段，以及原图/清晰图/缩略图/视频预览分开。它能定位“卡在找源”“只提交未完成”“转码失败”“上传被拒”，但前提是底层真的采集到了结果。没有原生终态回调时，台账只能如实记录未知，不能推导微信服务端为什么拒绝或退出登录。

P2 · 新旧策略并存旧策略、历史状态别名仍存在；handoff_association.review_turn内还可见SHA256/150秒旧检查。不能以字符串搜索替代调用路径核验。该兼容分支存在不等于七状态主视频链路重新依赖SHA256，也不能宣称所有分支彻底清理。后续清理需单独验证实际可达路径、保留旧版与frozen样本，不在本次文档工作中修改规则。

“同阶段重复”“较早证据补记”“保护已发布状态”本身不是错误。需要处理的是它们背后的未关联、证据缺口、同步停滞或错误分类。上述问题优先级是排查建议，不代表本次已修复。
