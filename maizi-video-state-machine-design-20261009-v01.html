单条视频状态机设计与代码

把人的动作、业务事件、Request 当前状态、规则与大模型分析结果彻底分开。目标不是让 AI 每次都猜对，而是让不确定判断永远不会悄悄推进正式状态。

聊天上下文驱动 事件溯源 版本级审批 人工兜底 可回放与审计

设计原则

正式状态只由已验证的业务事件推导。人的动作、大模型建议、提醒和人工校对任务都不能直接覆盖 requests.status。

可以自动确认

发送人身份明确、Request 唯一、目标版本唯一、消息语义明确、前置状态合法，并且没有相互冲突的证据。

必须人工校对

同群并行多个 Request、短回复没有引用、批量范围不清、同一句包含确认和修改、身份未知或版本无法唯一定位。

四层模型

1

人的动作

谁正在做什么。用于任务协作，不直接改变 Request 状态。

Human Action
2

业务事件

已经发生且有证据的事实。只追加，不覆盖历史。

Domain Event
3

业务状态

当前等待哪个结果。由全部正式事件重新计算。

Request State
4

分析与校对

规则或大模型的候选判断，以及人工接受、纠正或拒绝。

Analysis & Review
不能进入业务事件表：unknown_video、no_state_change、manual_review、likely_approved。它们只是分析结果。

允许自动写入业务事件的条件

  1. 消息未被处理过，保证幂等；
  2. 发送人身份和角色确定；
  3. Request 和版本唯一；
  4. 消息语义明确，不是疑问句或混合意见；
  5. 状态转换合法，所需前置事件齐全；
  6. 没有冲突审批或更新版本；
  7. 规则允许该类事件自动确认。

-- 核心约束示例；PostgreSQL 与 SQLite 需分别调整主键和时间类型
CREATE TABLE workflow_events (
  id TEXT PRIMARY KEY,
  request_id TEXT NOT NULL REFERENCES requests(id),
  event_type TEXT NOT NULL,
  artifact_version_id TEXT,
  actor_id TEXT,
  actor_role TEXT,
  evidence_message_uid TEXT,
  payload_json TEXT NOT NULL DEFAULT '{}',
  created_at TEXT NOT NULL,
  UNIQUE(request_id, event_type, evidence_message_uid)
);

CREATE TABLE approvals (
  id TEXT PRIMARY KEY,
  request_id TEXT NOT NULL REFERENCES requests(id),
  artifact_type TEXT NOT NULL CHECK (artifact_type IN ('script','cut')),
  artifact_version_id TEXT NOT NULL,
  reviewer_id TEXT NOT NULL,
  reviewer_role TEXT NOT NULL CHECK (reviewer_role IN ('doctor','company')),
  decision TEXT NOT NULL CHECK (decision IN ('approved','changes_requested')),
  evidence_message_uid TEXT NOT NULL,
  created_at TEXT NOT NULL,
  UNIQUE(artifact_version_id, reviewer_role, evidence_message_uid)
);

2. 校验业务事件，而不是相信分类结果
export function validateDomainEvent(context, event) {
  const errors = [];
  if (!context.request) errors.push('request_missing');
  if (!event.evidenceMessageUid) errors.push('evidence_missing');
  if (!roleCanEmit(event.actorRole, event.type)) errors.push('actor_role_forbidden');

  if (requiresVersion(event.type)) {
    if (!event.artifactVersionId) errors.push('version_missing');
    if (event.artifactVersionId !== context.currentVersionId) errors.push('stale_version');
  }

  if (!transitionAllowed(context.request.status, event.type)) {
    errors.push('illegal_transition');
  }
  return { ok: errors.length === 0, errors };
}
3. 根据事实重新计算状态
export function deriveRequestStatus(projection) {
  if (projection.cancelled) return REQUEST_STATUS.CANCELLED;
  if (projection.completed) return REQUEST_STATUS.COMPLETED;
  if (projection.observationDue) return REQUEST_STATUS.OBSERVATION_DUE;
  if (projection.published) return REQUEST_STATUS.PUBLISHED;
  if (projection.publicationScheduled) return REQUEST_STATUS.SCHEDULED;
  if (currentCutFullyApproved(projection)) return REQUEST_STATUS.READY_TO_PUBLISH;
  if (projection.currentCutNeedsChanges) return REQUEST_STATUS.AWAITING_CUT_REVISION;
  if (projection.currentCut) {
    if (projection.workType === 'patient_education' && !projection.companyCutApproved)
      return REQUEST_STATUS.AWAITING_COMPANY_CUT;
    return REQUEST_STATUS.AWAITING_DOCTOR_CUT;
  }
  if (projection.rawNeedsReplacement) return REQUEST_STATUS.AWAITING_RAW_REPLACEMENT;
  if (projection.rawQcApproved) return REQUEST_STATUS.AWAITING_CUT;
  if (projection.currentRaw) return REQUEST_STATUS.AWAITING_RAW_QC;
  if (currentScriptFullyApproved(projection)) return REQUEST_STATUS.AWAITING_RAW;
  if (projection.currentScript) {
    if (projection.doctorScriptApproved && projection.workType === 'patient_education')
      return REQUEST_STATUS.AWAITING_COMPANY_SCRIPT;
    return REQUEST_STATUS.AWAITING_DOCTOR_SCRIPT;
  }
  return REQUEST_STATUS.AWAITING_SCRIPT;
}
4. 人工校对后才生成正式事件
export function acceptHumanDecision(db, decision) {
  db.exec('BEGIN IMMEDIATE');
  try {
    const task = loadOpenReviewTask(db, decision.reviewTaskId);
    const event = buildDomainEvent(task, decision);
    const context = loadTransitionContext(db, event.requestId);
    const validation = validateDomainEvent(context, event);
    if (!validation.ok) throw new Error(validation.errors.join(','));

    insertHumanDecision(db, decision);
    insertWorkflowEvent(db, event);       // append-only + unique evidence
    rebuildRequestProjection(db, event.requestId);
    closeReviewTask(db, task.id);
    db.exec('COMMIT');
  } catch (error) {
    db.exec('ROLLBACK');
    throw error;
  }
}

当前代码与正式版本的差距

能力当前状态正式版本需要
发送人角色已有身份映射和未知身份保护增加人工修正并持久化
消息事件分类已有规则和可选大模型建议将分析结果与业务事件表彻底分离
上下文候选已有时间、数量和标题评分绑定正式 Request 与具体版本
状态机在内存中推进临时作品通过事件回放计算正式状态

文案/成片版本没有正式版本链不可覆盖、父版本关系、版本级审批
人工校对已有 CSVreview_tasks 和 human_decisions 入库
状态写入只读，不写业务状态事务、幂等、合法转换和状态重算
