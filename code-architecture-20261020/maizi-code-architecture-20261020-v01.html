02 / 从哪里读代码

主要是 Node.js ESM + Python 的模块化应用与独立 worker，并非完整拆分的微服务。网页使用原生 HTML、CSS、JavaScript；PowerShell 管进程和原生操作，C++ DLL 适配微信内部能力。

下表未写完整目录的文件均位于 tools/chat-viewer/；云端专有模块以发布快照为准。

03 / 四条主链路

A. 收到消息 → 员工看到消息

微信数据库变化 → refresh 采集 → archive.sqlite 提交 → sync-wake 唤醒 → cloud-sync 增量上传 → 云端查询副本 → SSE 通知浏览器刷新。文件通知外仍有恢复检查，防止漏通知后永远停住。图片和视频不阻塞这条文字消息链路。

B. 员工点击发送 → 微信发出

网页请求 → 云端身份与内容校验 → 发送 outbox → 本机 send-worker 领取 → 核对账号、进程、版本及发送上下文 → 原生适配执行 → 回传状态。进程中断等不确定结果保留为 unknown，不自动重复发送。微信消息归档继续提供后续回显；HTTP 接受请求不能等同于对方已读。

C. 媒体 → 可播放 / 可查看 / 可转写

先检查本机可用媒体；需要原生主动下载的图片、视频由下载协调器提交。视频的短时 DLL 在生命周期条件满足、回调释放并核实卸载后退出，外部程序继续等落盘；不是“调用返回就无条件卸载”。完整性验证后生成清晰图片预览、压缩视频预览或可播放语音，异步上传云端。图片原件留本地、按需提供；云端已有缓存可独立服务。

语音另走 Qwen 队列：领取 → 解码 WAV → Qwen → 保存结果 → 回传。近 7 天群语音在音频准备好后自动补齐，旧消息可手动请求。视频开头也使用 Qwen，但限配置的分析范围。转写失败不改变音频可播放状态。单附件 400 MB 的支持不代表所有收到原件都预先上传。

D. 群聊证据 → 作品进度 → 飞书

归档唤醒 task-state-worker → live_state → 稳定身份、医生群和唯一作品关联 → role_workflow 按科普/患教及当前稿件判断 → PostgreSQL 事务提交状态、历史、版本、游标和待同步项 → 异步 PATCH 飞书已有记录的作品进度 → 回读核验。未知身份、歧义引用、旧版本确认等保留待核对，不凭“可以”或最后一条作品猜归属。没有飞书行也可保留本地任务，不自动创建远端行。

04 / 为什么这样设计

选择收益代价 / 边界
本机接微信，云端面向员工网页可持续查询已有历史；原生能力集中在实际登录机器。本机断线后新消息、真实发送和未准备媒体会等待。
消息、媒体、ASR、状态 worker 分开转码或模型延迟不阻塞文字同步；失败可单独定位。最终一致：消息先出现，媒体和文字结果稍后补上。
SQLite 消息归档 + PostgreSQL 业务主库原始证据与可变业务状态各司其职；业务事务保证状态链一致。两个存储不是一个跨库事务；依靠稳定 UID、游标、幂等衔接。
事务 outbox + 回读本地提交后可恢复远端同步；保留审计来源。飞书无远端 CAS，存在并发编辑窗口；冲突暂停，不能宣称端到端 exactly-once。
原生操作互斥与短时下载适配下载提交期间协调发送，文件等待在外部完成。仍依赖微信内部 ABI；版本变动和账号安全验证风险没有消失。
预览上云，原件按需降低云盘占用与员工首屏等待。首次处理需本机在线；“预览清晰”不等于原件始终云端可用。
Qwen 托管 ASR本机不承担大型识别模型推理，中文转写与两类音频共用适配器。依赖网络、API 费用与第三方处理；音频会发送给 Qwen。尚无人工校对 ASR golden 准确率集。

当前需要留意的结构性问题

  • 源码与部署版本有漂移。本机 tools/chat-viewer/server.mjs 并不等于完整云端发布版；员工权限、跟进与部分媒体集成在发布快照中。部署必须基于当前完整版本做差异更新，不能整目录覆盖。
  • 模块边界存在，但文件夹较拥挤。运行模块、发布准备脚本、诊断工具和历史试验并列；后续适合整理为 runtime、media、native、deploy、tests，并明确唯一发布源。这里仅记录建议，未实施重构。
  • 企微代码仍留存不等于服务启用。云端历史兼容模块保留，个人微信功能与旧企微数据不能混为同一运行链路。
  • 模型输出是证据之一。识别文本、相似稿件候选与正式作品状态不是同一个概念，不能以 ASR 成功替代作品关联和审批核验。

05 / 测试与发布

项目规则：每次修改代码后、交付或部署前执行 golden 和受影响模块测试。测试失败先处理；不以语法检查替代。文档发布不重启业务服务。

npm run test:video-golden
python tools/chat-viewer/qwen-asr.test.py
python tools/chat-viewer/video-opening.test.py
node --test tools/chat-viewer/voice-transcripts.test.mjs

后面三条用于 ASR 相关修改；其他修改选择相应媒体、发送、权限或业务事务测试。PostgreSQL 集成测试使用专用临时测试库，不能连接生产库进行破坏性测试。

Golden 入口 tools/video-pilot/task-state-golden.py，固定集 fixtures/frozen/。当前 v4 为 23 个场景；含 v1–v3 共 77 次回放，不是 77 个不同业务样本。现有命令同时执行 100 项测试。两项真实本机媒体案例不包含在离线 golden 中；角色与作品关联是明确输入，通过不代表全群自动理解准确率。

.github/workflows/video-golden.yml 配置 push、PR 和手动触发，包含 Windows/Linux 回归与 PostgreSQL 集成。分支强制检查是否启用需另行核验；不能仅凭 YAML 声称已禁止失败合并。
