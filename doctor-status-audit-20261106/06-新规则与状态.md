# 规则目标、实现现状和操作边界

## 用户最新确认：共11个状态

| 状态 | 用途 | 触发 | 必须具备的证据 |
|---|---|---|---|
| 文案确认中 | 自动 | 文案人员交出实际稿件或修改稿 | 实际正文已取得，明确对应作品 |
| 文案修改中 | 自动 | 文案人员真实引用稿件并承接修改 | 文案职责、原生引用、被修改的稿件 |
| 待剪辑 | 自动 | 医生交付原片 | 原件核验、唯一作品匹配及适用范围 |
| 成片确认中 | 自动 | 剪辑人员交出成片或新版成片 | 实际成片及对应作品 |
| 剪辑中 | 自动 | 剪辑人员真实引用成片并承接修改 | 剪辑职责、原生引用、被修改的成片 |
| 待发布 | 自动 | 发布人员真实引用最终成片并承接发布 | 发布职责、真实引用、明确最终成片；医生说可以不够 |
| 已发布 | 自动 | 可核验的平台发布结果 | 具体作品与真实平台结果；承接话术不等于发布 |
| 已取消 | 仅人工 | 人工处理 | 自动规则不得覆盖 |
| 已下架 | 仅人工 | 人工处理 | 自动规则不得覆盖 |
| 已定时 | 保留，暂不用 | 以后使用 | 不得作为当前新规则的自动目标 |
| 待录制 | 保留，暂不用 | 以后使用 | 不得作为当前新规则的自动目标 |

## 当前实现与目标的差距

- 飞书主进度字段 `fldPwWdcpd` 回读只有前7个选项，后4个还未加入。此次只审计，没有修改字段。
- 数据库仍保留历史状态枚举及原始历史。`文案待医生确认` 显示为 `文案确认中`，`成片待医生确认` 显示为 `成片确认中`；不是新增的两个业务阶段。
- 当前版本 `handoff-seven-20261106-v1` 自动目标为7状态；`已取消`、`已下架` 是停止自动推进的保护状态。库中还有旧的暂停、异常等保护标签，不等于最新11状态字段已部署。
- 兼容旧任务时，代码仍允许从旧的 `待录制`、`已定时` 等状态接收某些有效交接；这与“暂时不使用”若意指完全不参与自动流转并不等价，后续实现需明确冻结还是仅禁止自动进入。
- 当前自动媒体规则限明确“科普”，且视频时长须超过150秒。原件可用仍须唯一匹配稿件；未知类型、未匹配视频留待核对。
- 发布结果入口当前要求结构化 publications 记录有确认人、确认时间、平台、URL、平台视频ID，并与对应作品视频一致。不是自动访问所有平台验证，飞书显示“已发布”也不能冒充平台核验完成。
- 视频原件校验和流转不再要求视频 SHA256，使用源消息关联、已验证目录和文件身份；文档、音频等其他校验仍可能保留哈希。
- 飞书自动同步、自动建作品及元数据填充已关闭。文档白名单已记录，但运行程序所有写入路径的18人强制白名单尚未完整验收，不能恢复原先全表写入。

## 飞书写入边界

只允许指定 Base 的医生视频表中原有18位医生所属作品的“作品进度”状态值。不得改其他医生，不得改其他字段、表或视图，不得增删医生和作品。18人以原医生目录记录ID确定；缺失或歧义关联不写入。此次审计是只读，不授权修复字段、补关联或合并任务。

## 判定原则

状态不一致先核对来源。飞书人工设置已发布、取消、下架时不能用早期本地状态回退。真实引用、职责、正文、原件、作品关联、发布结果缺一项时，应明确卡点，不能用一句承接话术代替证据。每次尝试和纠偏保留原记录及新结果。
