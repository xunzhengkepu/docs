# 微信聊天判断视频流程：扩大样本可行性结论

生成日期：2026-10-09。只读分析，不修改聊天归档和业务状态。

## 结论

- **能做**：在发送人身份已知、并且消息出现“视频剪好/修改好/可以发布/需要修改”等明确文字时，可以判断流程事件和后续状态。
- **不能仅靠现有消息稳定完成**：无法可靠证明某条员工成片对应哪一条医生原片。直接视频只有 `[视频]`，没有媒体 ID、文件哈希或逐条标题。
- 因此，可先把系统定位为“状态提醒和人工校对助手”，不能直接作为无需复核的完整视频转换台账。

## 数据范围

- 10 个医生对接群，2026-06-04 至 2026-10-09。
- 4,580 条消息，859 条视频消息，合并为 640 个视频批次。
- 224 个医生原片批次，251 个员工成片批次，165 个发送人身份未识别的视频批次。
- 从 251 个员工成片批次中按群和时间分层抽取 60 个，人工阅读前后上下文。

## 实测结果

| 判断目标 | 结果 | 说明 |
|---|---:|---|
| 视频发送人角色可识别 | 475 / 640（74.2%） | 其余 25.8% 因 sender_id 或身份映射缺失，暂不能判断原片/成片 |
| 员工成片附近有后续文字 | 243 / 251（96.8%） | 其中包含数字、分隔线等弱文本 |
| 明确出现剪好、修改好、终版、发布等动作词 | 201 / 251（80.1%） | 适合做高精度事件触发 |
| 规则能在 24 小时内绑定明确审核/修改/发布结果 | 140 / 251（55.8%） | 只统计无需人工复核的规则结果；当前规则偏保守 |
| 60 条人工样本中，后续状态从文字可明确判断 | 42 / 60（70.0%） | 这是可判率；尚未经过业务员工独立标注，不能当作正式准确率 |
| 成片只有一个原片候选 | 6 / 251（2.4%） | 大多数群同时存在多条原片 |
| 成片存在多个原片候选 | 235 / 251（93.6%） | 时间和数量不足以唯一对应 |
| 原片候选第一名领先第二名至少 15 分 | 28 / 251（11.2%） | 仍是推断，不是文件级证明 |

## 对“准确率”的解释

当前可以计算的是**可判率/覆盖率**，还不能诚实给出生产准确率。正式准确率需要员工对样本填写真实结果，再比较系统输出。

本次人工阅读显示：

1. 对明确文字事件，判断通常直接且稳定，例如“视频剪好了”“修改好了”“没问题”“请发布”。
2. 对没有文字、只有图片/表情/语音，或同一时间连续发多条视频的情况，结果容易歧义。
3. 对“哪条原片变成哪条成片”，即使时间很近也经常有多个候选。现有聊天数据不能证明唯一关系。

## 最小试点边界

只自动生成以下高确定性结果：

- 已识别医生发送 `[视频]`：记录“收到原片候选”；
- 已识别剪辑发送 `[视频]`，附近明确写“剪好/修改好/终版”：记录“收到成片候选”；
- 医生紧接着明确写“没问题/可以发”：建议变为“审核通过”；
- 医生紧接着明确提出修改：建议变为“待修改”。

“原片 A 对应成片 B”继续标记为待人工确认。
